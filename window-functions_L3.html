Nested Windows & CTE Patterns

Window functions can't nest directly. Use CTE to chain: inner CTE computes window, outer applies another window. This enables complex patterns like 'moving average of ranks' or 'rank of running totals'.
nested windows via CTE
-- Moving average of row numbers (smooth rank)
WITH ranked AS (
  SELECT 
    name,
    salary,
    ROW_NUMBER() OVER (ORDER BY salary) AS rn
  FROM employees
)
SELECT 
  name,
  salary,
  rn,
  AVG(rn) OVER (ORDER BY rn ROWS BETWEEN 2 PRECEDING AND CURRENT ROW) AS smooth_rank
FROM ranked;

-- Running total of ranks
WITH ranked AS (
  SELECT *, ROW_NUMBER() OVER (ORDER BY salary) AS rn FROM employees
)
SELECT 
  name,
  rn,
  SUM(rn) OVER (ORDER BY rn) AS running_rn
FROM ranked;

Performance — work_mem, Spills, Indexes

work_mem & Spilling

work_mem tuning
-- Check for spills
EXPLAIN ANALYZE SELECT ROW_NUMBER() OVER (ORDER BY salary) FROM employees;

-- Increase work_mem
SET work_mem = '256MB';

-- For parallel: per-worker work_mem

Spill = massive slowdown. Window functions sort entire partition. If partition > work_mem → disk spill. Increase work_mem or reduce partition size (add PARTITION BY).

Dialect Deep Dive — Window Function Support

ANSI SQL 
SELECT ROW_NUMBER() OVER (PARTITION BY dept ORDER BY salary) FROM emp;
PostgreSQL 
Full support: all frame types, EXCLUDE, GROUPS, IGNORE NULLS
MySQL 
MySQL 8.0+: ROW_NUMBER, RANK, DENSE_RANK, LAG, LEAD, NTILE, FIRST_VALUE, LAST_VALUE, frame clauses
Python (pandas) 
df.groupby('dept')['salary'].rank()
Python (SQLAlchemy) 
func.row_number().over(partition_by=Emp.dept, order_by=Emp.salary.desc())
ANSI SQL 
LAST_VALUE(x) OVER (ORDER BY ts ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING)
PostgreSQL 
Requires explicit frame for LAST_VALUE. Supports IGNORE NULLS.
MySQL 
LAST_VALUE requires frame clause. No IGNORE NULLS.
Python (pandas) 
df['col'].transform('last')
Python (SQLAlchemy) 
func.last_value(Emp.col).over(...)

Glossary

nested windowWindow function applied to result of another window function via CTE.
WindowAggPostgreSQL executor node for window functions. Multiple passes for different functions.
work_memMemory budget for sort/hash/window operations per query. Spills to disk if exceeded.
CTE materializationPG12+ inlines single-reference CTEs (pushdown-friendly) and materializes multi-reference ones. A materialized CTE is computed once but acts as an optimization fence: outer predicates are not pushed into it.
Sort Method: external mergeEXPLAIN ANALYZE indicator that sort spilled to disk (work_mem exceeded).
peer groupRows with identical ORDER BY values. Relevant for RANGE/GROUPS frames and EXCLUDE TIES.
