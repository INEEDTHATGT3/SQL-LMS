Compound Predicates — AND, OR, NOT, Precedence

AND before OR — always. Parentheses are documentation that the optimizer respects. Write (A AND B) OR C, not A AND B OR C.
boolean logic
-- Precedence: NOT > AND > OR
-- A AND B OR C  means  (A AND B) OR C

-- Be explicit
SELECT * FROM employees 
WHERE (salary > 50000 AND dept_id = 1) 
   OR (salary > 60000 AND dept_id = 2);

-- NOT distributes (De Morgan)
SELECT * FROM employees WHERE NOT (dept_id = 3 OR salary < 30000);
-- Equivalent:
SELECT * FROM employees WHERE dept_id <> 3 AND salary >= 30000;

Subquery IN / EXISTS — The NULL Trap

IN vs EXISTS with Subqueries

in with subquery
-- IN subquery
SELECT * FROM employees 
WHERE dept_id IN (SELECT id FROM departments WHERE location = 'NYC');

-- Equivalent EXISTS (often better)
SELECT * FROM employees e
WHERE EXISTS (
  SELECT 1 FROM departments d 
  WHERE d.id = e.dept_id AND d.location = 'NYC'
);

-- NOT IN trap: if subquery returns ANY NULL, whole thing is UNKNOWN
SELECT * FROM employees WHERE dept_id NOT IN (SELECT id FROM departments WHERE location = 'NYC');
-- If subquery has NULL → ZERO rows returned!

-- Safe: NOT EXISTS
SELECT * FROM employees e
WHERE NOT EXISTS (
  SELECT 1 FROM departments d 
  WHERE d.id = e.dept_id AND d.location = 'NYC'
);

Advanced CASE — Expression, Nesting, Pivot Prep

Searched CASE for Complex Logic

searched case patterns
-- Multiple conditions, first match wins
SELECT name, salary,
  CASE
    WHEN salary >= 100000 AND dept_id = 1 THEN 'Eng Senior'
    WHEN salary >= 100000 THEN 'Senior'
    WHEN salary >= 70000 THEN 'Mid'
    ELSE 'Junior'
  END AS level
FROM employees;

-- CASE in WHERE (filter by derived category)
SELECT * FROM (
  SELECT *, 
    CASE WHEN salary >= 100000 THEN 'high' ELSE 'normal' END AS pay_band
  FROM employees
) t WHERE pay_band = 'high';

-- CASE in ORDER BY (custom sort)
SELECT * FROM employees
ORDER BY 
  CASE status WHEN 'active' THEN 1 WHEN 'pending' THEN 2 ELSE 3 END,
  salary DESC;

CASE for Pivot/Crosstab Preparation

conditional aggregation (pivot prep)
-- Count by status per department
SELECT dept_id,
  COUNT(*) FILTER (WHERE status = 'active') AS active_cnt,
  COUNT(*) FILTER (WHERE status = 'pending') AS pending_cnt,
  COUNT(*) FILTER (WHERE status = 'inactive') AS inactive_cnt
FROM employees
GROUP BY dept_id;

-- Same with CASE (portable)
SELECT dept_id,
  SUM(CASE WHEN status = 'active' THEN 1 ELSE 0 END) AS active_cnt,
  SUM(CASE WHEN status = 'pending' THEN 1 ELSE 0 END) AS pending_cnt,
  SUM(CASE WHEN status = 'inactive' THEN 1 ELSE 0 END) AS inactive_cnt
FROM employees
GROUP BY dept_id;

-- FILTER clause (PostgreSQL) — cleaner, index-friendly
SELECT dept_id,
  COUNT(*) FILTER (WHERE status = 'active') AS active_cnt
FROM employees GROUP BY dept_id;
-- No FILTER; use CASE
SELECT dept_id,
  SUM(CASE WHEN status = 'active' THEN 1 ELSE 0 END) AS active_cnt
FROM employees GROUP BY dept_id;

Dialect Differences — Boolean & String

ANSI SQL 
SELECT * FROM t WHERE a AND b OR c;
PostgreSQL 
SELECT * FROM t WHERE a AND b OR c; -- (a AND b) OR c
MySQL 
SELECT * FROM t WHERE a AND b OR c; -- Same precedence
Python (pandas) 
df[(df['a'] & df['b']) | df['c']]  # & before |
Python (SQLAlchemy) 
session.query(T).filter(or_(and_(T.a, T.b), T.c)).all()
ANSI SQL 
SELECT * FROM t WHERE name LIKE 'A%'; -- case-sensitive
PostgreSQL 
SELECT * FROM t WHERE name ILIKE 'A%'; -- case-insensitive
MySQL 
SELECT * FROM t WHERE name LIKE 'A%'; -- case-insensitive (default collation)
Python (pandas) 
df[df['name'].str.startswith('A', case=False)]
Python (SQLAlchemy) 
session.query(T).filter(T.name.ilike('A%')).all()

60-second revision card

RE-READ BEFORE ANY INTERVIEW / CONTEST

  • Precedence: NOT > AND > OR. Parenthesize: (A AND B) OR C
  • De Morgan: NOT (A OR B) = NOT A AND NOT B; NOT (A AND B) = NOT A OR NOT B
  • NOT IN (subquery) + NULL = zero rows. Use NOT EXISTS or filter NULLs
  • EXISTS stops at first match; IN scans all. EXISTS often faster for NOT
  • CASE: first WHEN wins; use in SELECT, WHERE, ORDER BY
  • FILTER (PostgreSQL) = portable CASE SUM for conditional aggregation

Glossary

short-circuit evaluationAND stops at first FALSE; OR stops at first TRUE. ORDER BY CASE leverages this.
anti-joinNOT EXISTS pattern — returns rows with no match in subquery.
semi-joinEXISTS / IN pattern — returns rows with at least one match; stops at first.
three-valued logicTRUE, FALSE, UNKNOWN. WHERE keeps TRUE only; CHECK constraint rejects FALSE only.
conditional aggregationCASE inside SUM/COUNT to pivot rows into columns per group.
FILTER clausePostgreSQL: aggregate FILTER (WHERE cond) — cleaner than CASE, index-friendly.
