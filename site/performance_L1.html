Mental Model — The Library Catalog

An index is like a library catalog. Without it, you scan every book (Seq Scan). With it, you jump straight to the shelf (Index Scan). But catalogs take space and slow down writes — use wisely.
  • Seq Scan: reads every page sequentially — O(N) but sequential I/O
  • Index Scan: B-tree lookup + heap fetch — O(log N + K) but random I/O
  • Index Only Scan: all columns in index — no heap fetch
  • Bitmap Index Scan: combines multiple indexes, builds bitmap, then heap fetch

BANALYZE is faster
CEXPLAIN shows actual rows
DNo difference

Buffers in EXPLAIN (ANALYZE, BUFFERS) show:
AMemory usage
BShared hit/read/dirtied blocks
CCPU usage
DNetwork I/O
Buffers show shared hit (cache), shared read (disk), dirtied (modified), written (flushed).
EXPLAIN ANALYZE shows 'Actual Rows=1000, Plan Rows=100' — what does this mean?
APlan was perfect
BPlanner underestimated by 10x
CQuery returned fewer rows
DIndex is corrupted
Planner estimated 100 rows but actual was 1000. Statistics may be stale (run ANALYZE).
In EXPLAIN (ANALYZE, BUFFERS), 'shared read' blocks mean the server…
Amissed the buffer cache and fetched pages from disk
Bused the CPU cache
Cwrote new WAL records
Dhit the network
Shared read counts page reads that missed the buffer cache; shared hit counts the ones answered from cache.

Indexes — B-tree, Composite, Partial, Covering

B-tree Index Basics

create index
-- Single column
CREATE INDEX idx_emp_salary ON employees (salary);

-- Composite (order matters!)
CREATE INDEX idx_emp_dept_salary ON employees (dept_id, salary DESC);

-- Partial (filtered)
CREATE INDEX idx_active_emp ON employees (salary) WHERE status = 'active';

-- Covering (INCLUDE)
CREATE INDEX idx_emp_salary_name ON employees (salary) INCLUDE (name);

-- Expression index
CREATE INDEX idx_emp_annual ON employees ((salary * 12));

-- Drop index
DROP INDEX idx_emp_salary;

60-second revision card

RE-READ BEFORE ANY INTERVIEW / CONTEST

  • EXPLAIN = plan; EXPLAIN ANALYZE = plan + actuals
  • Seq Scan = full table; Index Scan = B-tree lookup + heap fetch; Index Only Scan = no heap fetch
  • Composite index: leading column first; (a,b) works for WHERE a=1 but not WHERE b=2
  • Partial index = WHERE clause on index; smaller, faster for filtered queries
  • Covering index (INCLUDE): all needed columns in index → Index Only Scan
  • Expression index: index on f(col) for WHERE f(col) = ?

Glossary

Seq ScanSequential scan — reads every table page sequentially.
Index ScanUses B-tree index to find matching rows, then fetches from heap.
Index Only ScanAll required columns in index; no heap fetch needed.
Bitmap Index ScanCombines multiple indexes via bitmap; good for AND/OR conditions.
Partial IndexIndex with WHERE clause — only indexes subset of rows.
Covering IndexIndex with INCLUDE columns — satisfies query without heap access.
