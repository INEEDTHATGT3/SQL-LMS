LATERAL Join Internals & Optimization

LATERAL = correlated subquery in FROM. Execution: for each left row, evaluate right subquery with left row's values as parameters. Index on (partition_col, order_col) enables index seek + LIMIT per left row.
lateral execution model
-- For each employee, get latest order
SELECT e.name, o.order_date, o.total
FROM employees e
LEFT JOIN LATERAL (
  SELECT order_date, total
  FROM orders o
  WHERE o.emp_id = e.id
  ORDER BY o.order_date DESC
  LIMIT 1
) o ON true;

-- Equivalent correlated subquery (harder to optimize)
SELECT e.name,
  (SELECT order_date FROM orders o WHERE o.emp_id = e.id ORDER BY order_date DESC LIMIT 1) AS latest_date,
  (SELECT total FROM orders o WHERE o.emp_id = e.id ORDER BY order_date DESC LIMIT 1) AS latest_total
FROM employees e;

Recursive CTE Internals — Working Table Iteration

Recursive CTE Execution Model

PostgreSQL recursive CTE uses working table / recursive table iteration:
1. Evaluate anchor query → initial working table
2. While working table not empty:
a. Run recursive query using working table as input
b. Result → next working table
c. Append to recursive table
d. Working table = next working table
3. Return recursive table
Each iteration processes one 'level' of recursion.

Qualify Clause (MySQL/Snowflake) vs CTE (PostgreSQL)

qualify vs cte
-- MySQL / Snowflake: QUALIFY filters window results
SELECT * FROM (
  SELECT *, ROW_NUMBER() OVER (PARTITION BY dept ORDER BY salary DESC) AS rn
  FROM employees
) WHERE rn <= 3;
-- With QUALIFY:
SELECT *, ROW_NUMBER() OVER (PARTITION BY dept ORDER BY salary DESC) AS rn
FROM employees
QUALIFY rn <= 3;

-- PostgreSQL: CTE required
WITH ranked AS (
  SELECT *, ROW_NUMBER() OVER (PARTITION BY dept ORDER BY salary DESC) AS rn
  FROM employees
)
SELECT * FROM ranked WHERE rn <= 3;

Dialect Mastery — Subquery/CTE Gaps

ANSI SQL 
WITH cte AS NOT MATERIALIZED (SELECT * FROM t WHERE x > 5) SELECT * FROM cte WHERE y = 1;
PostgreSQL 
WITH cte AS NOT MATERIALIZED (SELECT * FROM t WHERE x > 5) SELECT * FROM cte WHERE y = 1; -- PG 12+
MySQL 
-- No NOT MATERIALIZED; CTE always materialized. Use subquery for pushdown:
SELECT * FROM (SELECT * FROM t WHERE x > 5) AS cte WHERE y = 1;
Python (pandas) 
# No CTE; filter chain
cte = df[df['x'] > 5]
result = cte[cte['y'] == 1]
ANSI SQL 
SELECT * FROM t1 LEFT JOIN LATERAL (SELECT * FROM t2 WHERE t2.id = t1.id LIMIT 1) t2 ON true;
PostgreSQL 
SELECT * FROM t1 LEFT JOIN LATERAL (SELECT * FROM t2 WHERE t2.id = t1.id LIMIT 1) t2 ON true;
MySQL 
SELECT * FROM t1 LEFT JOIN LATERAL (SELECT * FROM t2 WHERE t2.id = t1.id LIMIT 1) t2 ON true; -- 8.0.14+
Python (pandas) 
t1.merge(t2.groupby('id').head(1), left_on='id', right_on='t2_id', how='left')
