Mental Model — The Nested Box

A subquery is a query inside another query. Think of it as a nested box: the inner box produces a value (or list of values) that the outer box uses. CTEs are named boxes you can reuse.
  • Scalar subquery: exactly 1 row, 1 column — use with =, >, <, etc.
  • Row subquery: exactly 1 row, multiple columns — use with row constructors
  • Table subquery: multiple rows — use with IN, EXISTS, NOT IN, FROM
  • Correlated subquery: references outer query columns — runs per outer row
  • CTE: named temporary result — reusable, readable, can be recursive

Table Subqueries — IN, EXISTS, NOT IN

Table Subquery — Multiple Rows

in / exists / not in
-- IN: value in subquery result
SELECT * FROM employees
WHERE dept_id IN (SELECT id FROM departments WHERE location = 'NYC');

-- EXISTS: correlated, stops at first match
SELECT * FROM employees e
WHERE EXISTS (
  SELECT 1 FROM orders o WHERE o.emp_id = e.id
);

-- NOT IN: watch for NULLs!
SELECT * FROM employees
WHERE dept_id NOT IN (SELECT id FROM departments WHERE active = true);
-- If subquery returns ANY NULL → zero rows!

-- NOT EXISTS: safe alternative
SELECT * FROM employees e
WHERE NOT EXISTS (
  SELECT 1 FROM departments d 
  WHERE d.id = e.dept_id AND d.active = false
);

NOT IN + subquery with NULL = zero rows. If subquery returns any NULL, entire NOT IN evaluates to UNKNOWN. Always use NOT EXISTS or filter NULLs: NOT IN (SELECT ... WHERE col IS NOT NULL).
subquery in FROM (derived table)
-- Derived table in FROM
SELECT dept_id, avg_sal
FROM (
  SELECT dept_id, AVG(salary) AS avg_sal
  FROM employees
  GROUP BY dept_id
) dept_avg
WHERE avg_sal > 50000;

-- Lateral join (PG) - subquery references outer columns
SELECT e.name, latest.order_date
FROM employees e
LEFT JOIN LATERAL (
  SELECT order_date FROM orders o
  WHERE o.emp_id = e.id
  ORDER BY order_date DESC LIMIT 1
) latest ON true;

NOT IN (subquery) with NULL in subquery returns:
AAll rows
BNo rows
CRows matching non-NULL values
DError
NOT IN with NULL → UNKNOWN for all rows → zero rows. Use NOT EXISTS instead.
EXISTS vs IN for 'has orders' query:
AEXISTS always faster
BIN always faster
CEXISTS stops at first match; IN may scan all
DSame performance

CTEs — Common Table Expressions

CTE Syntax & Benefits

basic cte
-- Single CTE
WITH high_paid AS (
  SELECT * FROM employees WHERE salary > 100000
)
SELECT * FROM high_paid WHERE dept_id = 1;

-- Multiple CTEs
WITH 
  active AS (SELECT * FROM employees WHERE status = 'active'),
  dept_avg AS (SELECT dept_id, AVG(salary) AS avg_sal FROM employees GROUP BY dept_id)
SELECT a.name, d.avg_sal
FROM active a
JOIN dept_avg d ON a.dept_id = d.dept_id;

-- CTE in subquery
SELECT * FROM (
  WITH cte AS (SELECT * FROM employees WHERE salary > 50000)
  SELECT * FROM cte
) t WHERE dept_id = 1;

Recursive CTE — Hierarchical Data

recursive cte
-- Employee hierarchy: find all reports under manager
WITH RECURSIVE org_chart AS (
  -- Anchor: top-level manager
  SELECT id, name, manager_id, 0 AS level
  FROM employees
  WHERE manager_id IS NULL

  UNION ALL

  -- Recursive: find direct reports
  SELECT e.id, e.name, e.manager_id, oc.level + 1
  FROM employees e
  JOIN org_chart oc ON e.manager_id = oc.id
  WHERE oc.level < 10  -- prevent infinite recursion
)
SELECT * FROM org_chart ORDER BY level, name;

Recursive CTE = anchor + recursive part. Always include termination condition (level limit or WHERE NOT EXISTS) to prevent infinite loops.

BReusable, readable, can be recursive
CUses less memory
DAuto-optimizes

COnly anchor + recursive part
DOnly termination condition

RE-READ BEFORE ANY INTERVIEW / CONTEST

  • Subquery types: scalar (1x1), row (1xN), table (MxN) — each with specific operators
  • Scalar subquery = single value; use with =, >, <, in expressions
  • Table subquery: IN, EXISTS, NOT IN, NOT EXISTS, FROM
  • NOT IN + NULL = disaster; use NOT EXISTS instead
  • CTE: WITH name AS (...) — reusable, readable, recursive capable
  • Recursive CTE: anchor + UNION ALL + recursive part + termination
