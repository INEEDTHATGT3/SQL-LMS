Predicate Pushdown — Moving Filters Down

Push predicates down to data source. Filter early = fewer rows to join/aggregate. CTEs, views, subqueries — all can block or allow pushdown. NOT MATERIALIZED = pushdown enabled. MATERIALIZED/volatile = pushdown blocked.
predicate pushdown examples
-- View with filter
CREATE VIEW active_users AS SELECT * FROM users WHERE status = 'active';
-- Query: SELECT * FROM active_users WHERE dept_id = 5;
-- Pushdown: status='active' AND dept_id=5 pushed into view scan

-- CTE with NOT MATERIALIZED (PG 12+)
WITH active AS NOT MATERIALIZED (
  SELECT * FROM users WHERE status = 'active'
)
SELECT * FROM active WHERE dept_id = 5;
-- dept_id=5 pushed into CTE scan

-- Subquery pushdown
SELECT * FROM (
  SELECT * FROM users WHERE status = 'active'
) u WHERE dept_id = 5;
-- Pushdown works (subquery merged)

-- Blocked by: VOLATILE functions, LIMIT/OFFSET in subquery, set operations, window functions

-- Blocked by: LIMIT in subquery, UNION, user variables

Pushdown blockers: VOLATILE functions (random(), now()), LIMIT/OFFSET in subquery, UNION/EXCEPT/INTERSECT, window functions in subquery, CTEs (materialized by default), multiple CTE references.

AFrom outer query INTO inner subquery/CTE
BFrom inner TO outer
CTo application layer

CTE Optimization Patterns

When to MATERIALIZE vs NOT MATERIALIZED

cte materialization control
-- Force inlining (pushdown)
WITH cte AS NOT MATERIALIZED (
  SELECT * FROM large_table WHERE status = 'active'
)
SELECT * FROM cte WHERE created > '2024-01-01';
-- Predicate pushed into scan

-- Force materialization (prevent re-computation)
WITH cte AS MATERIALIZED (
  SELECT * FROM large_table WHERE status = 'active'
)
SELECT * FROM cte WHERE dept = 1;
SELECT * FROM cte WHERE dept = 2;
-- CTE computed once, reused

Advanced Recursive CTE Patterns

Advanced Recursion Patterns

advanced recursive patterns
-- Cycle detection with path tracking
WITH RECURSIVE paths AS (
  SELECT id, parent_id, name, ARRAY[id] AS path, 1 AS depth
  FROM nodes WHERE parent_id IS NULL

  UNION ALL

  SELECT n.id, n.parent_id, n.name, p.path || n.id, p.depth + 1
  FROM nodes n
  JOIN paths p ON n.parent_id = p.id
  WHERE n.id != ALL(p.path)  -- cycle prevention
  AND p.depth < 20
)
SELECT * FROM paths;

-- Shortest path (BFS via level)
WITH RECURSIVE bfs AS (
  SELECT id, ARRAY[id] AS path, 0 AS dist
  FROM nodes WHERE id = 'A'

  UNION ALL

  SELECT n.id, p.path || n.id, p.dist + 1
  FROM edges e
  JOIN bfs p ON e.from_id = p.id
  JOIN nodes n ON e.to_id = n.id
  WHERE n.id != ALL(p.path)
  AND p.dist < 10
)
SELECT * FROM bfs WHERE id = 'Z' ORDER BY path LIMIT 1;

-- Transitive closure (all reachable)
WITH RECURSIVE reachable AS (
  SELECT from_id, to_id FROM edges WHERE from_id = 1

  UNION ALL

  SELECT r.from_id, e.to_id
  FROM reachable r
  JOIN edges e ON e.from_id = r.to_id
  WHERE e.to_id != ALL(ARRAY[r.from_id] || r.to_id)
)
SELECT DISTINCT to_id FROM reachable;
