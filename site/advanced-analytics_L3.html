Approximate Aggregates — HyperLogLog, TDigest, KMV

Exact COUNT(DISTINCT) = O(N) memory. Approximate = O(1) memory, ~1-2% error. HyperLogLog for distinct count, TDigest for percentiles, KMV for top-K. Essential for 1B+ row tables.
hyperloglog distinct count
-- PostgreSQL: HyperLogLog extension
CREATE EXTENSION IF NOT EXISTS hll;

-- Create HLL sketch
SELECT hll_add_agg(hll_empty(), user_id) FROM events;

-- Distinct count from sketch
hll_cardinality(hll_add_agg(hll_empty(), user_id));

-- Merge sketches (parallel/distributed)
hll_union(hll_sketch1, hll_sketch2);

HyperLogLog memory usage is:
AO(N) where N = distinct count
BO(log N)

HLL uses fixed-size registers (e.g., 2^14 registers = ~16KB). Memory constant regardless of distinct count.

Streaming Analytics — Continuous Views, PipelineDB, pg_streaming

Continuous Aggregates (TimescaleDB)

continuous aggregate
-- TimescaleDB continuous aggregate
CREATE MATERIALIZED VIEW hourly_events
WITH (timescaledb.continuous) AS
SELECT time_bucket('1 hour', time) AS bucket,
  device_id,
  COUNT(*) AS event_count,
  AVG(value) AS avg_value
FROM events
GROUP BY bucket, device_id;

-- Automatic refresh (background)
SELECT add_continuous_aggregate_policy('hourly_events',
  start_offset => INTERVAL '3 hours',
  end_offset => INTERVAL '1 hour',
  schedule_interval => INTERVAL '1 hour');

-- Real-time view (combines materialized + raw)
SELECT * FROM hourly_events WHERE bucket > now() - INTERVAL '1 day';
