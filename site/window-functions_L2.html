Frame Clauses — ROWS vs RANGE

Frame = window boundaries. ROWS = physical row count. RANGE = ORDER BY value + offset. Default = RANGE UNBOUNDED PRECEDING TO CURRENT ROW. Always specify frame for LAST_VALUE, running totals, moving averages.
frame syntax
-- ROWS: physical row count
SUM(amount) OVER (
  ORDER BY sale_date
  ROWS BETWEEN 3 PRECEDING AND CURRENT ROW
) AS moving_sum_4days

-- RANGE: value-based (ORDER BY must be numeric/date)
SUM(amount) OVER (
  ORDER BY sale_date
  RANGE BETWEEN INTERVAL '3 days' PRECEDING AND CURRENT ROW
) AS moving_sum_3days

-- Unbounded
SUM(amount) OVER (
  ORDER BY sale_date
  ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
) AS total_so_far

NTILE — Bucketing Rows

NTILE(n) — Equal-Size Buckets

ntile
-- Quartiles (4 buckets)
SELECT 
  name,
  salary,
  NTILE(4) OVER (ORDER BY salary) AS quartile
FROM employees;

-- Deciles (10 buckets)
SELECT 
  name,
  salary,
  NTILE(10) OVER (ORDER BY salary) AS decile
FROM employees;

-- Per department
SELECT 
  dept_id,
  name,
  salary,
  NTILE(4) OVER (PARTITION BY dept_id ORDER BY salary) AS dept_quartile
FROM employees;

NTILE distributes rows as evenly as possible. If rows % n ≠ 0, first buckets get 1 extra row. NTILE(4) on 10 rows → buckets: 3,3,2,2 rows.
NTILE(4) on 10 rows → bucket sizes:
A2,2,3,3
B3,3,2,2
C2,2,2,4
D3,2,2,3
Extra rows go to first buckets. 10/4 = 2 remainder 2 → first 2 buckets get 3 rows.
NTILE with PARTITION BY dept_id — buckets per partition:
AAcross all departments combined
BSeparate buckets per department
COnly works without PARTITION BY
DError
NTILE respects PARTITION BY — each partition gets its own buckets 1..n.

Advanced Frames — EXCLUDE, GROUPS

Frame Exclusion — EXCLUDE CURRENT ROW

exclude current row
-- Sum of OTHER employees' salaries in same dept
SELECT 
  name,
  salary,
  SUM(salary) OVER (
    PARTITION BY dept_id
    ORDER BY salary
    ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    EXCLUDE CURRENT ROW
  ) AS sum_other_salaries
FROM employees;

-- Exclude group (all tied peers)
SUM(salary) OVER (
  PARTITION BY dept_id
  ORDER BY salary
  RANGE BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
  EXCLUDE GROUP
) AS sum_other_tiers

-- Exclude ties
SUM(salary) OVER (
  PARTITION BY dept_id
  ORDER BY salary
  RANGE BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
  EXCLUDE TIES
) AS sum_other_tiers

GROUPS Frame (PostgreSQL 14+)

groups frame
-- GROUPS: counts groups of peer rows (same ORDER BY value)
-- 1 group = all rows with same ORDER BY value
SELECT 
  salary,
  COUNT(*) OVER (
    ORDER BY salary
    GROUPS BETWEEN 1 PRECEDING AND 1 FOLLOWING
  ) AS peer_count
FROM employees;

Percentile & Distribution Functions

PERCENT_RANK, CUME_DIST, PERCENTILE_CONT/DISC

distribution functions
-- Percent rank (0 to 1)
SELECT 
  name,
  salary,
  PERCENT_RANK() OVER (ORDER BY salary) AS pct_rank,
  CUME_DIST() OVER (ORDER BY salary) AS cume_dist
FROM employees;

-- PERCENT_RANK = (rank - 1) / (total - 1)
-- CUME_DIST = rank / total  (includes ties)

-- Percentile aggregates (ordered-set aggregates)
SELECT 
  percentile_cont(0.5) WITHIN GROUP (ORDER BY salary) AS median,
  percentile_disc(0.5) WITHIN GROUP (ORDER BY salary) AS median_discrete,
  percentile_cont(0.95) WITHIN GROUP (ORDER BY salary) AS p95
FROM employees;

PERCENT_RANK vs CUME_DIST for value at position 3 of 10:
ASame
BPERCENT_RANK=0.2, CUME_DIST=0.3
CPERCENT_RANK=0.3, CUME_DIST=0.2
DBoth 0.2
PERCENT_RANK = (rank-1)/(N-1). CUME_DIST = rank/N. For rank 3 of 10: (3-1)/9=0.22 vs 3/10=0.3.
percentile_cont(0.95) returns:
A95th percentile (interpolated)
B95th percentile (actual value)
CTop 5% rows
DTop 5% average
percentile_cont interpolates between values for exact percentile.
