Table Partitioning — Scale Without Sharding

Partitioning = physical split, logical unity. Large table becomes many small tables. Planner prunes partitions automatically. Maintenance (VACUUM, indexes) per partition.
range partitioning (PostgreSQL 11+)
-- Parent table
CREATE TABLE measurements (
  log_id BIGSERIAL,
  sensor_id INT NOT NULL,
  log_time TIMESTAMPTZ NOT NULL,
  value NUMERIC
) PARTITION BY RANGE (log_time);

-- Monthly partitions
CREATE TABLE measurements_2024_01 PARTITION OF measurements
  FOR VALUES FROM ('2024-01-01') TO ('2024-02-01');
CREATE TABLE measurements_2024_02 PARTITION OF measurements
  FOR VALUES FROM ('2024-02-01') TO ('2024-03-01');

-- Default partition (catches strays)
CREATE TABLE measurements_default PARTITION OF measurements DEFAULT;

-- Index on parent = created on all partitions
CREATE INDEX idx_meas_sensor_time ON measurements (sensor_id, log_time);
# Python version pending — add after validation.
-- Same syntax
-- Attach/detach for rolling windows
ALTER TABLE measurements DETACH PARTITION measurements_2023_01;
ALTER TABLE measurements ATTACH PARTITION measurements_2025_01
  FOR VALUES FROM ('2025-01-01') TO ('2025-02-01');
-- MySQL 8.0+ partitioning
CREATE TABLE measurements (
  log_id BIGINT AUTO_INCREMENT,
  sensor_id INT NOT NULL,
  log_time DATETIME NOT NULL,
  value DECIMAL(10,2),
  PRIMARY KEY (log_id, log_time)
) PARTITION BY RANGE (UNIX_TIMESTAMP(log_time)) (
  PARTITION p202401 VALUES LESS THAN (UNIX_TIMESTAMP('2024-02-01')),
  PARTITION p202402 VALUES LESS THAN (UNIX_TIMESTAMP('2024-03-01')),
  PARTITION pmax VALUES LESS THAN MAXVALUE
);

Append cost=0..42.15 rows=3200 width=72
Index Scan on measurements_2024_01 cost=0.29..21.07 rows=1600

Partition pruning: Only 2 of 12 monthly partitions scanned. Query on Jan-Feb touches only those partitions. Detach old partitions for instant archival.
Partition pruning works when:
AQuery filters on partition key
BAny WHERE clause is used
CIndex exists on partition key
DTable has > 10 partitions
Planner only skips partitions if WHERE clause constrains the partition key (log_time in example).
Unique constraint on partitioned table requires:
APartition key included in unique columns
BNo unique constraints allowed
CGlobal unique index
DAll partitions same size
PostgreSQL requires partition key in PRIMARY KEY / UNIQUE to enforce uniqueness within single partition.

Hash Cond: (a.id = b.id)
Parallel Hash Join workers each build:
AFull hash table on entire build side
BHash table on their partition of build side
CShared hash table in shared memory
DNo hash table — use NLJ

ASame thing

CGather Merge faster
DGather for Hash Join only

Expression must be IMMUTABLE. No NOW(), random(), volatile functions. Expression index stores computed value — if function isn't immutable, index becomes inconsistent.
BRIN index size is ~1/30th of B-tree because:
AIt uses compression
BStores only min/max per block range, not every row
COnly indexes first column
DSkips NULL values
BRIN summarizes 128-page ranges (default) with min/max. Tiny metadata vs per-row pointers.
CREATE INDEX CONCURRENTLY cannot:
ARun inside a transaction
BBe used on partitioned tables
CCreate unique indexes
DWork on expressions
Must run outside transaction. Takes share-update-exclusive lock, not exclusive.

Glossary

partition pruningPlanner excludes partitions not matching WHERE on partition key.
partition keyColumn(s) used to determine which partition a row belongs to.
parallel queryMultiple workers scan/process data simultaneously; leader gathers results.
pages_per_rangeBRIN parameter: how many heap pages per min/max summary. Lower = more precise, larger index.
gather mergeParallel workers return sorted data; leader merges without re-sorting.
concurrent indexIndex built without blocking writes; takes share-update-exclusive lock.
