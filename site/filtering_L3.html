Sargability — Write Predicates That Use Indexes

SARGable = Search ARGument ABLE. Predicate can use index seek. Non-sargable → Seq Scan. Rule: column naked on one side, constant on other. No functions, no math, no implicit casts on column.
sargable vs non-sargable
-- SARGABLE (index seek)
WHERE created_at >= '2024-01-01'
WHERE name LIKE 'Alice%'
WHERE dept_id IN (1,2,3)
WHERE salary > 50000

-- NON-SARGABLE (Seq Scan)
WHERE UPPER(name) = 'ALICE'           -- function on column
WHERE created_at + INTERVAL '1 day' > NOW()  -- math on column
WHERE YEAR(created_at) = 2024         -- function
WHERE salary * 1.1 > 55000            -- math
WHERE name LIKE '%smith'              -- leading wildcard
WHERE status = 'active' OR status = 'pending'  -- OR often kills index
# Python version pending — add after validation.
-- Partial index makes OR sargable for known values
CREATE INDEX idx_status_active ON employees (id) WHERE status IN ('active','pending');
-- Functional index (MySQL 8.0+)
CREATE INDEX idx_email_lower ON users ((LOWER(email)));

Implicit cast kills index too. WHERE varchar_col = 123 casts column to numeric → Seq Scan. WHERE numeric_col = '123' is fine (constant cast). Always match types.
WHERE date_col + 1 > '2024-01-01' is non-sargable because:
ADate math not supported
BFunction/math on column prevents index use
C> operator not indexed
DLiteral format wrong
Any computation on column (math, function, cast) prevents B-tree traversal.

AAlways Seq Scan
BIndex seek on partial index
CBitmap scan only
DDepends on PostgreSQL version

Functional & Partial Indexes — Make Non-Sargable Sargable

Functional Index — Index the Expression

functional index
-- Query: WHERE LOWER(email) = 'alice@x.com'
-- BAD: Seq Scan
-- FIX: Functional index
CREATE INDEX idx_users_email_lower ON users (LOWER(email));

-- Now query uses index!
EXPLAIN SELECT * FROM users WHERE LOWER(email) = 'alice@x.com';
-- Index Scan using idx_users_email_lower

-- Case-insensitive unique constraint
CREATE UNIQUE INDEX idx_users_email_ci ON users (LOWER(email));
-- Prevents 'Alice@x.com' and 'alice@x.com' both existing
# Python version pending — add after validation.
-- PostgreSQL: expression index
CREATE INDEX idx ON users (LOWER(email));
-- Supports any immutable function
-- MySQL 8.0+: functional index
CREATE INDEX idx_email_lower ON users ((LOWER(email)));
-- Note: double parentheses required

Partial Index — Index Only What You Query

partial index
-- 90% queries: WHERE status = 'active'
-- Full index wastes space on 'inactive', 'deleted'
CREATE INDEX idx_emp_active ON employees (salary) WHERE status = 'active';

-- Size: fraction of full index
-- Query uses it:
SELECT * FROM employees WHERE status = 'active' AND salary > 50000;
-- Index Scan on idx_emp_active

-- Partial unique: one 'active' per email
CREATE UNIQUE INDEX idx_email_active ON users (email) WHERE status = 'active';
-- Allows 'alice@x.com' in 'inactive' + 'active'

-- Partial index (PostgreSQL native)

-- MySQL: no native partial index
-- Workaround: partitioned table or filtered index via generated column

A partial index WHERE status = 'active' is eligible only when the query predicate targets that same constant:
AWHERE status = 'inactive'
BWHERE status = 'active' AND salary > 50k
CWHERE salary > 50k (no status filter)

Advanced Patterns — NULLS FIRST/LAST, Boolean Index

NULL Ordering in Indexes

nulls first/last
-- Index with NULLs last (default in PG)
CREATE INDEX idx_name ON users (name);
-- NULLs sort last in ASC

-- Explicit NULLS FIRST/LAST
CREATE INDEX idx_name_nulls_first ON users (name ASC NULLS FIRST);

-- Query matching order
SELECT * FROM users ORDER BY name ASC NULLS FIRST;
-- Uses idx_name_nulls_first

-- Descending
CREATE INDEX idx_salary_desc ON employees (salary DESC NULLS LAST);

Boolean Column — Partial Index for True/False

boolean partial index
-- Table: is_deleted BOOLEAN DEFAULT FALSE
-- 99% FALSE, queries only need non-deleted
CREATE INDEX idx_not_deleted ON items (id) WHERE NOT is_deleted;

-- Query:
SELECT * FROM items WHERE NOT is_deleted AND created_at > '2024-01-01';

60-second revision card

RE-READ BEFORE ANY INTERVIEW / CONTEST

  • SARGable: column naked on left, constant on right. No functions/math/casts on column
  • Functional index: index the expression (LOWER, math) to make non-sargable sargable
  • Partial index: WHERE clause on index — smaller, faster for skewed access patterns
  • Predicate pushdown: move filter to storage layer; key in distributed/columnar DBs
  • Covering index (INCLUDE): index-only scan, avoids heap fetch
  • Implicit cast on column = Seq Cast. Match types: numeric_col = 123 not '123'

Glossary

sargableSearch ARGument ABLE — predicate that can use index seek (e.g., col = 5).
functional indexIndex on expression (e.g., LOWER(col)) — supports queries using that expression.
partial indexIndex with WHERE clause — only indexes subset of rows matching condition.
covering indexIndex with INCLUDE columns — satisfies query without heap lookup.
predicate pushdownMoving filter predicate down to storage/index layer to reduce data movement.
implicit castAutomatic type conversion on column (e.g., varchar = 123) — kills index.
