dynamic pivot function
CREATE OR REPLACE FUNCTION monthly_sales_pivot()
RETURNS SETOF record
LANGUAGE plpgsql AS $$
DECLARE
  col_list text;
BEGIN
  SELECT string_agg(format('%I numeric', 'm' || extract(month from d)), ', ' ORDER BY d)
    INTO col_list
    FROM (SELECT DISTINCT date_trunc('month', order_date)::date AS d FROM orders) s;

  RETURN QUERY EXECUTE format(
    'SELECT * FROM crosstab(''SELECT region, date_trunc(''month'', order_date)::date AS m, SUM(amount) FROM orders GROUP BY 1, 2 ORDER BY 1, 2'',
                            ''SELECT DISTINCT date_trunc(''month'', order_date)::date AS m FROM orders ORDER BY 1'')
     AS ct (region text, %s)',
    col_list
  );
END;
$$;

The fixed query hard-codes m1..m3; the function builds col_list from the months actually present, then interpolates it into the crosstab output declaration with %s. New months appear automatically without editing the report — that is the whole point of a dynamic pivot. When the category set is user-controlled, %I (identifier) quoting is what keeps a month name from becoming SQL structure.

Identifier injection. Never glue user-supplied category names into a pivot with plain ||. format('%I', name) double-quotes and escapes the identifier; %L would quote a literal. A category value that becomes a column name is code, and must be quoted as such.
Why format('%I') for dynamically-built identifiers?
AIt quotes and escapes the identifier against injection
BIt is faster than ||
CIt only works in DO blocks
DIt uppercases identifiers
%I quotes the identifier with double quotes and escapes embedded quotes, so a malicious product name cannot turn into SQL structure.

Rolling Analytics Metrics You Can Tune

custom window aggregate
-- Custom moving-average aggregate: rolling analytics you can tune
CREATE FUNCTION mov_avg_sfunc(state internal, val numeric, window_start int, window_end int)
RETURNS internal LANGUAGE C AS '...';

CREATE FUNCTION mov_avg_final(state internal)
RETURNS numeric LANGUAGE C AS '...';

-- Moving window support for O(1) sliding
CREATE FUNCTION mov_avg_msfunc(state internal, val numeric, window_start int, window_end int)
RETURNS internal LANGUAGE C AS '...';

CREATE FUNCTION mov_avg_minvfunc(state internal, val numeric, window_start int, window_end int)
RETURNS internal LANGUAGE C AS '...';

CREATE AGGREGATE mov_avg(numeric) (
  SFUNC = mov_avg_sfunc,
  STYPE = internal,
  FINALFUNC = mov_avg_final,
  MSFUNC = mov_avg_msfunc,
  MINVFUNC = mov_avg_minvfunc,
  WINDOW = true
);

-- Usage: O(1) sliding average over a rolling 3-day window
SELECT emp_id,
       hire_date,
       salary,
       mov_avg(salary) OVER (ORDER BY hire_date
                             ROWS BETWEEN 2 PRECEDING AND CURRENT ROW) AS rolling_avg
FROM employees;

Moving window support needs both msfunc and minvfunc: msfunc folds a new value in, minvfunc removes the value leaving the frame. Without minvfunc the server recomputes each window from scratch — O(k) per row instead of O(1). This is C-level machinery; PL/pgSQL cannot supply inverse transition functions.
EXPLAIN — Custom Window Aggregate PostgreSQL
WindowAgg cost=60..550 rows=8500 width=48
Sort cost=60..220 rows=8500 width=40
Seq Scan on employees cost=0..185 rows=8500 width=40

The WindowAgg node sorts by the window ORDER BY, then slides the aggregate state across the frame. With msfunc/minvfunc the per-row transition cost is constant regardless of window width — the difference between a 3-day and a 90-day rolling metric collapses to zero. Tuning the aggregate (adding weights, decay, or session-aware state) is a matter of writing the transition functions, not the query.

Which transition pair lets a custom aggregate slide a window in constant time?
AO(k) per row
BMSFUNC adds in / MINVFUNC subtracts out
CParallel execution
DA final function only
msfunc adds the new value, minvfunc removes the old one — O(1) per slide vs O(k) recompute.
Authoring a custom aggregate for a moving window means you must supply…
APL/pgSQL transition functions only
BSFUNC/STYPE plus MSFUNC and inverse MINVFUNC
CA Python extension
DA parallel-combine function, nothing else
Transition functions must be fast and IMMUTABLE; the msfunc/minvfunc pair lets the window slide incrementally.

LAG(sales) IGNORE NULLS backfills a sparse series: it skips rows where the value is NULL and attaches the most recent non-NULL figure to the current row — the classic pattern for non-trading days, partial reporting, or telemetry gaps, without inventing data.

Triggers & Transaction Control — Audit, Constraints, Cascades

CREATE TRIGGER — BEFORE / AFTER / INSTEAD OF

audit triggers
-- AFTER ROW: capture who changed what
CREATE TABLE emp_audit (
  op      text NOT NULL,
  emp_id  int  NOT NULL,
  changed_at timestamptz NOT NULL DEFAULT now(),
  changed_by text NOT NULL DEFAULT current_user
);

CREATE FUNCTION log_emp_change() RETURNS trigger
LANGUAGE plpgsql AS $$
BEGIN
  INSERT INTO emp_audit VALUES (TG_OP, NEW.id);
  RETURN NEW;
END;
$$;

CREATE TRIGGER emp_audit_ai
AFTER INSERT OR UPDATE ON employees
FOR EACH ROW EXECUTE FUNCTION log_emp_change();

INSTEAD OF on views

instead of trigger
-- Make a view writable via INSTEAD OF
CREATE VIEW emp_full AS
SELECT e.id, e.name, d.name AS dept
FROM employees e JOIN departments d ON d.id = e.dept_id;

CREATE FUNCTION emp_full_insert() RETURNS trigger
LANGUAGE plpgsql AS $$
BEGIN
  INSERT INTO departments(name) VALUES (NEW.dept)
    ON CONFLICT (name) DO NOTHING;
  INSERT INTO employees(id, name, dept_id)
    SELECT NEW.id, NEW.name, id FROM departments WHERE name = NEW.dept;
  RETURN NEW;
END;
$$;

CREATE TRIGGER emp_full_ioi
INSTEAD OF INSERT ON emp_full
FOR EACH ROW EXECUTE FUNCTION emp_full_insert();

Constraint enforcement & audit hygiene

validation trigger
-- Cross-table invariant a plain FK can't express
CREATE FUNCTION check_room_capacity() RETURNS trigger
LANGUAGE plpgsql AS $$
DECLARE cap int;
BEGIN
  SELECT capacity INTO cap FROM rooms WHERE id = NEW.room_id;
  IF (SELECT COUNT(*) FROM bookings
       WHERE room_id = NEW.room_id
         AND tstzrange(date, date + duration) &&
             tstzrange(NEW.date, NEW.date + NEW.duration)) >= cap
  THEN
    RAISE EXCEPTION 'room % is over capacity', NEW.room_id;
  END IF;
  RETURN NEW;
END;
$$;

CREATE TRIGGER bookings_cap_before
BEFORE INSERT OR UPDATE ON bookings
FOR EACH ROW EXECUTE FUNCTION check_room_capacity();

ATables
BViews
CMaterialized views
DIndexes
INSTEAD OF is the view-writability mechanism; tables get BEFORE/AFTER row triggers.
RAISE EXCEPTION inside a BEFORE trigger:
AContinues the INSERT
BAborts the statement and rolls back the transaction
COnly logs a warning
DSkips the row silently
An uncaught exception aborts the transaction — the standard way to enforce invariants beyond FK constraints.

Glossary

msfunc/minvfuncTransition functions that add (msfunc) and remove (minvfunc) a value from a moving-aggregate window state.
moving aggregateA window aggregate whose state slides with the frame via inverse transition functions (O(1) per row).
hypothetical setA function answering 'where would this value rank?' without inserting any row.
ordered-set aggregateAn aggregate with a WITHIN GROUP (ORDER BY ...) argument, e.g. RANK(x) WITHIN GROUP.
WITHIN GROUPClause supplying the ORDER BY and argument for ordered-set aggregates (RANK, percentiles).
INSTEAD OF triggerA view-level trigger that intercepts a write and runs your procedure instead of the default action.
dynamic pivotA crosstab whose category columns are built at runtime from the data, quoted with %I to stay safe.
