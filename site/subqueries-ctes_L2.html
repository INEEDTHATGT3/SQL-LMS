Correlated Subqueries — Per-Row Evaluation

Correlated subquery = parameterized inner query. For each outer row, inner query runs with outer row's values as parameters. Powerful but can be slow — consider JOIN or LATERAL for performance.
correlated subquery patterns
-- Correlated in WHERE
SELECT * FROM employees e
WHERE salary > (
  SELECT AVG(salary) FROM employees e2 WHERE e2.dept_id = e.dept_id
);

-- Correlated in SELECT (per row)
SELECT 
  e.name,
  e.salary,
  (SELECT AVG(salary) FROM employees e2 WHERE e2.dept_id = e.dept_id) AS dept_avg
FROM employees e;

-- Correlated with EXISTS (semi-join)
SELECT * FROM employees e
WHERE EXISTS (
  SELECT 1 FROM orders o WHERE o.emp_id = e.id AND o.total > 1000
);

LATERAL Joins — Correlated Subquery in FROM

LATERAL — The Powerful Correlated Subquery

lateral basics
-- For each employee, get latest order
SELECT e.name, o.order_date, o.total
FROM employees e
LEFT JOIN LATERAL (
  SELECT order_date, total
  FROM orders o
  WHERE o.emp_id = e.id
  ORDER BY o.order_date DESC
  LIMIT 1
) o ON true;

-- Equivalent correlated subquery (less readable)
SELECT e.name,
  (SELECT order_date FROM orders o WHERE o.emp_id = e.id ORDER BY order_date DESC LIMIT 1) AS latest_date,
  (SELECT total FROM orders o WHERE o.emp_id = e.id ORDER BY order_date DESC LIMIT 1) AS latest_total
FROM employees e;

CTE Optimization — Materialization & Pushdown

CTE Materialization & Inlining

cte materialization control
-- PostgreSQL 12+: control materialization
WITH cte AS NOT MATERIALIZED (
  SELECT * FROM large_table WHERE status = 'active'
)
SELECT * FROM cte WHERE dept_id = 5;
-- Predicate dept_id=5 pushed into CTE scan

-- Force materialization (default for recursive, volatile functions)
WITH cte AS MATERIALIZED (
  SELECT * FROM large_table WHERE status = 'active'
)
SELECT * FROM cte WHERE dept_id = 5;

-- Default: materialized if referenced multiple times, or has volatile functions

Recursive CTE Patterns — Graphs, Trees, Paths

Recursive CTE Patterns

recursive patterns
-- Path enumeration: find path from A to B
WITH RECURSIVE paths AS (
  SELECT id, name, ARRAY[id] AS path, 1 AS depth
  FROM nodes WHERE id = 'A'

  UNION ALL

  SELECT n.id, n.name, p.path || n.id, p.depth + 1
  FROM nodes n
  JOIN paths p ON n.parent_id = p.id
  WHERE n.id != ALL(p.path)  -- prevent cycles
  AND p.depth < 10
)
SELECT * FROM paths WHERE id = 'B';

-- Level-order traversal (breadth-first)
WITH RECURSIVE bfs AS (
  SELECT id, name, 0 AS level
  FROM employees WHERE manager_id IS NULL

  UNION ALL

  SELECT e.id, e.name, b.level + 1
  FROM employees e
  JOIN bfs b ON e.manager_id = b.id
)
SELECT * FROM bfs ORDER BY level;

RE-READ BEFORE ANY INTERVIEW / CONTEST

  • Correlated subquery: runs per outer row; use EXISTS for semi-join, LATERAL for set results
  • LATERAL: right side sees left columns; CROSS JOIN LATERAL = inner, LEFT JOIN LATERAL = outer
  • EXISTS stops at first match; IN may scan all. Use EXISTS for correlated semi/anti joins
  • CTE: NOT MATERIALIZED for pushdown, MATERIALIZED to force; recursive = anchor + UNION ALL + recurse
  • Recursive CTE: track visited (path array), limit depth, prevent cycles
  • NOT IN + NULL = zero rows; always NOT EXISTS for anti-join
