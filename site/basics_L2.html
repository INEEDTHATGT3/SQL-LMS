Advanced Filtering — IN, NOT IN, LIKE, BETWEEN

WHERE is your precision tool. IN for lists, LIKE for patterns, BETWEEN for ranges. Chain with AND/OR — parentheses control precedence.
IN / NOT IN
-- Multiple values
SELECT * FROM employees WHERE dept_id IN (1, 3, 5);

-- Exclude
SELECT * FROM employees WHERE dept_id NOT IN (2, 4);

-- Subquery (preview)
SELECT * FROM employees WHERE dept_id IN (SELECT id FROM departments WHERE location = 'NYC');

-- Starts with

-- Ends with

-- Contains
SELECT * FROM employees WHERE name LIKE '%son%';

-- Single char wildcard: _
SELECT * FROM employees WHERE name LIKE 'J_n';  -- Jan, Jon, Jun

SELECT * FROM employees WHERE name ILIKE 'a%';

WHERE status IN ('active', 'pending') is equivalent to:
Astatus = 'active' AND status = 'pending'
Bstatus = 'active' OR status = 'pending'
Cstatus BETWEEN 'active' AND 'pending'
Dstatus LIKE 'active%'

AAny string containing 'test'
BStrings ending with 'test' plus one char
CStrings starting with 'test'

Compound Conditions — AND, OR, NOT, Precedence

boolean logic
-- AND has higher precedence than OR
-- This: salary > 50000 AND dept = 1 OR dept = 2
-- Means: (salary > 50000 AND dept = 1) OR dept = 2

-- Use parentheses for clarity
SELECT * FROM employees 
WHERE (salary > 50000 AND dept_id = 1) 
   OR (salary > 60000 AND dept_id = 2);

-- NOT
SELECT * FROM employees WHERE NOT (dept_id = 3 OR salary < 30000);

Query Plans — Reading EXPLAIN

What is a Query Plan?

EXPLAIN shows how the database *will* execute your query. It reveals: scan type (Seq Scan vs Index Scan), join method, estimated cost, and row counts. At L2, focus on: Seq Scan = full table read (slow for large tables), Index Scan = targeted lookup (fast).

Seq Scan vs Index Scan PostgreSQL
Seq Scan on employees as e cost=0..185 rows=8500 width=72 actual time=0.024..12.45 actual rows=3200 loops=1
Filter: (salary > 50000)
With Index on salary PostgreSQL
Index Scan on employees as e cost=0.29..42.15 rows=3200 width=72 actual time=0.018..3.12 actual rows=3200 loops=1
Index Cond: (salary > 50000)
Cost dropped from 185 → 42. Time from 12ms → 3ms. Index Scan reads only matching rows; Seq Scan reads entire table. At L3 you'll learn when indexes *don't* help.
A Seq Scan reads:
AOnly indexed columns
BEvery row in the table
COnly the first 100 rows
DRows in index order
Sequential Scan = full table scan. Reads all pages sequentially.
Index Cond in EXPLAIN means:
AIndex is corrupted
BIndex is being used for filtering
CIndex needs rebuilding
DFull index scan
Index Cond shows the condition applied during index lookup.

Dialect Differences — String Concatenation

ANSI SQL 
SELECT first_name || ' ' || last_name AS full_name FROM employees;
PostgreSQL 
SELECT first_name || ' ' || last_name AS full_name FROM employees;
MySQL 
SELECT CONCAT(first_name, ' ', last_name) AS full_name FROM employees;
Python (pandas) 
employees['full_name'] = employees['first_name'] + ' ' + employees['last_name']
Python (SQLAlchemy) 
session.query((Employee.first_name + ' ' + Employee.last_name).label('full_name')).all()
ANSI & PostgreSQL use ||. MySQL uses CONCAT(). In MySQL, || is logical OR unless PIPES_AS_CONCAT mode enabled.

Glossary

Seq ScanSequential scan — reads every table page; O(N) cost.
Index ScanUses B-tree index to jump directly to matching rows; O(log N) + matches.
wildcard% (any chars) and _ (one char) in LIKE patterns.
precedenceOrder of operations: NOT > AND > OR. Parentheses override.
paginationLIMIT n OFFSET m — skip m rows, take n. Page k = OFFSET k*page_size.
costPlanner's estimated resource units (not milliseconds). Lower = better.
