Mental Model — The Filter Funnel

WHERE is a funnel: rows enter, predicates test each row, only passing rows exit. Order of predicates doesn't change results (optimizer reorders), but can change performance.

Imagine pouring a bucket of rows through a series of screens. Each screen = a predicate (salary > 50000, status = 'active', etc.). Rows that match pass through; others are caught. The final stream is your result set.

  • Each predicate = independent true/false test per row
  • AND = all screens must pass; OR = any screen passes
  • NOT = invert the screen
  • NULL fails all comparisons (=, <, >, LIKE, IN) — use IS NULL

Pattern Matching — LIKE, ILIKE

LIKE Wildcards

like patterns
-- Starts with
SELECT * FROM employees WHERE name LIKE 'A%';

-- Ends with
SELECT * FROM employees WHERE email LIKE '%@company.com';

-- Contains
SELECT * FROM employees WHERE name LIKE '%son%';

-- Single char: _
SELECT * FROM employees WHERE name LIKE 'J_n';  -- Jan, Jon, Jun

-- Escape literal % or _
SELECT * FROM employees WHERE code LIKE '100\%%' ESCAPE '\\';

SELECT * FROM employees WHERE name ILIKE 'a%';

-- SIMILAR TO (regex-like)
SELECT * FROM employees WHERE name SIMILAR TO '[A-C]%';
-- Case-insensitive by default
SELECT * FROM employees WHERE name LIKE 'a%';

-- REGEXP for regex
SELECT * FROM employees WHERE name REGEXP '^[A-C]';

Conditional Logic — CASE, COALESCE, NULLIF

CASE Expression

case basics
-- Simple CASE (equality)
SELECT name,
  CASE dept_id
    WHEN 1 THEN 'Engineering'
    WHEN 2 THEN 'Sales'
    WHEN 3 THEN 'Marketing'
    ELSE 'Other'
  END AS department
FROM employees;

-- Searched CASE (conditions)
SELECT name, salary,
  CASE
    WHEN salary >= 100000 THEN 'Senior'
    WHEN salary >= 70000 THEN 'Mid'
    ELSE 'Junior'
  END AS level
FROM employees;

NULL Handling — COALESCE, NULLIF

coalesce / nullif
-- COALESCE: first non-NULL
SELECT COALESCE(manager_id, 0) AS mgr FROM employees;
-- If manager_id is NULL, returns 0

-- NULLIF: returns NULL if equal
SELECT NULLIF(status, '') FROM employees;
-- Empty string becomes NULL

-- Combined: normalize then coalesce
SELECT COALESCE(NULLIF(TRIM(phone), ''), 'N/A') FROM employees;

60-second revision card

RE-READ BEFORE ANY INTERVIEW / CONTEST

  • IN = multiple OR; NOT IN = multiple AND (watch for NULLs in subquery!)
  • BETWEEN = inclusive range; works on numbers, dates, strings
  • LIKE: % = any chars, _ = one char; leading % kills index
  • PostgreSQL: ILIKE for case-insensitive; MySQL: LIKE is case-insensitive by default
  • CASE: simple (equality) vs searched (conditions); always include ELSE
  • COALESCE = first non-NULL; NULLIF(a,b) = NULL if a=b else a

Glossary

predicateBoolean expression in WHERE/HAVING that evaluates per row.
sargableSearch ARGument ABLE — predicate that can use index (e.g., col = 5, not UPPER(col) = 'X').
wildcard% (zero+ chars) and _ (exactly one char) in LIKE patterns.

simple CASECASE expr WHEN val THEN result — equality checks against expr.
